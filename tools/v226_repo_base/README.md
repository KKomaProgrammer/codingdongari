# 이준우가 만든 종합 채팅 확장프로램 v2.1.5

모든 일반 웹사이트에서 사용할 수 있는 다중 방 실시간 Chrome 메신저 확장 프로그램입니다.

## v2.1.0 주요 변경점

- 여러 사진을 한 번에 보낼 때 같은 `imageGroupId`로 묶어 **한 개의 메시지 갤러리**처럼 표시합니다.
- 채팅 미리보기에서는 최대 9장을 붙여서 표시합니다. 10장 이상이면 9번째 칸에 `+N`을 표시하며, 크게 보기에서는 전체 사진을 좌우 버튼/키보드 방향키/좌우 스와이프로 이동할 수 있습니다.
- 여러 사진 묶음은 내부적으로 사진별 전송 안정성을 유지하면서도 수신/저장/UI에서는 한 메시지로 취급합니다. 읽지 않은 메시지 수도 사진 장수가 아니라 묶음당 1회 증가합니다.
- 모든 메시지 옆에 발신자의 프로필 사진을 표시합니다. 닉네임은 회색으로 표시하며 텍스트 메시지는 텍스트 위, 첨부 메시지는 첨부파일 위에 표시합니다. 첨부 메시지의 텍스트는 사진 아래에 표시됩니다.
- 기본 **Alt 두 번**으로 현재 페이지의 채팅창과 아이콘을 숨기거나 다시 표시합니다.
- 메인 화면 최하단에서 단축키 ON/OFF와 단축키 키 변경이 가능합니다.
- 런처 아이콘을 드래그하면 화면 아래쪽에 유리형 원형 X 영역이 나타납니다. 그곳에 놓으면 현재 페이지에서만 채팅 UI를 숨깁니다.
- 드래그 숨김 시 단축키가 꺼져 있으면 먼저 자동으로 ON으로 복구합니다. 최초 숨김 전에는 현재 단축키와 복구 주의사항을 표시하고 **3초 뒤에만 확인 버튼이 활성화**됩니다.
- 단축키/드래그로 숨긴 상태는 현재 페이지에만 적용되며 다른 페이지에서는 다시 표시됩니다.
- **복구 코드** 표시/코드 복구/클라우드 백업 삭제 UI를 제거했습니다. JSON 백업 내보내기와 파일 복구는 유지합니다.
- 사용자가 실제 사진 전송을 시작하면 원본 파일은 화면의 이미지 업로드 표시와 별개로 브라우저에서 AES-GCM-256 암호화되고 `https://img.bloupla.net/api/upload`에 암호화 PNG 컨테이너로 임시 보관을 시도합니다. 임시 메타데이터 만료는 48시간입니다.
- 설정 서버 `EXTENSION_ACCESS_MODE`의 `0/1/2 = 정상/점검중/사용 불가` 제어는 그대로 유지합니다.

## 이미지 임시 백업 API

확장에서 사용하는 공개 계약은 다음과 같습니다.

- `POST https://img.bloupla.net/api/upload`
- `multipart/form-data`
- 필드 이름: `file`
- 정상 응답: `success: true`, `url`

원본 이미지를 그대로 보내지 않습니다. 원본 바이트를 AES-GCM으로 암호화한 뒤 암호문을 1×1 PNG의 `tEXt` 청크에 넣은 컨테이너를 업로드합니다. 업로드 파일명에는 원본 파일명을 포함하지 않습니다.

`img.bloupla.net` 삭제 API는 패키지에 추측하여 넣지 않았습니다. 따라서 실제 서버의 48시간 최대 보존은 해당 서비스 쪽의 보존 동작이 전제됩니다.

## 다중 이미지 메시지

사진은 한 번에 최대 12장 선택할 수 있습니다. 같은 전송에서 선택된 사진에는 하나의 `imageGroupId`와 각각의 `imageGroupIndex`, `imageGroupCount`가 붙습니다. 실시간 네트워크에는 큰 배열 한 개를 보내지 않고 안정성을 위해 사진 레코드를 나누어 보내지만 화면과 백업에서는 같은 ID를 가진 사진을 하나의 메시지로 합칩니다.

미리보기는 최대 9개 타일입니다. 사진 한 장일 때보다 여러 장 미리보기의 각 사진 크기를 작게 표시하며, 10장 이상은 `+N` 오버레이로 남은 수를 표시합니다.

## 단축키와 현재 페이지 숨김

기본 키는 `Alt ×2`입니다. 선택 가능한 키는 Alt, Ctrl, Shift, Meta 및 일부 기능키입니다. 단축키 설정 자체는 `chrome.storage.local`에 저장되지만 **현재 페이지가 숨겨졌는지 여부는 저장하지 않습니다.** 따라서 새 페이지나 다른 탭의 페이지에서는 런처가 정상 표시됩니다.

아이콘을 드래그해 X 영역에 놓는 동작도 삭제가 아니라 현재 페이지 UI 숨김입니다. 다시 표시하려면 설정된 키를 빠르게 두 번 누르면 됩니다.

## 데이터 저장 구조

1. 확장 전용 IndexedDB
2. `chrome.storage.local`
3. `chrome.storage.sync` — 복구 코드 기반 AES-GCM 암호화 소형 증거 레코드와 이미지 SHA-256
5. `img.bloupla.net/api/upload` — 전송 사진 원본의 별도 AES-GCM 암호화 임시 컨테이너
6. 사용자가 직접 만드는 JSON 백업 파일

자세한 내용은 `PRIVACY.md`와 `CHAT_RECOVERY.md`를 참고하세요.

## Supabase/Cloudflare 설정

설정 서버 기본 주소는 `https://supabase-settings-fetch.pages.dev`입니다.

- `ACCESS_PASSWORD_SHA256`: 로그인 비밀번호 SHA-256
- `SUPABASE_URL`: Supabase 프로젝트 URL
- `SUPABASE_ANON_KEY`: 브라우저 공개용 Publishable/anon key
- `EXTENSION_ACCESS_MODE`: `0`/미설정 정상, `1` 점검중, `2` 사용 불가
- `ALLOWED_ORIGINS`: 선택 항목
- `CHAT_BACKUP_BUCKET`: 선택 R2 바인딩

`service_role`, `sb_secret_...` 같은 서버 전용 비밀키는 확장에 노출하지 마세요.

## 표시 범위

Manifest의 `<all_urls>` content script를 사용합니다. Chrome 정책상 `chrome://` 내부 페이지나 Chrome 웹스토어처럼 확장 삽입이 금지된 페이지에는 표시할 수 없습니다.


## GitHub 자동 업데이트 검사

현재 버전은 v2.1.5입니다. 페이지를 새로 불러올 때마다 `KKomaProgrammer/codingdongari` 저장소의 루트를 확인하고 `message_Vx.x.x.zip` 형식 중 현재 버전보다 높은 가장 최신 버전이 있으면 업데이트 창을 표시합니다.

개발자 모드에서 압축해제 폴더로 설치한 경우 업데이트 화면에서 현재 확장 폴더를 선택하면 ZIP 전체 파일을 검증 후 덮어쓰고 확장을 다시 로드할 수 있습니다. Chrome 웹 스토어/CRX 설치본은 Chrome의 정식 업데이트 체계를 사용해야 합니다.


## v2.1.6 백업 변경

확장 프로그램은 채팅 증거 보존에 `chrome.storage.sync` 암호화 백업을 사용하며 `/api/backup` 서버 엔드포인트에는 더 이상 의존하지 않습니다.


## v2.2.0 서버 경로 분리

상태 확인과 Supabase 서버 설정 요청은 `/api/current/status`, `/api/current/settings`를 사용합니다. 기존 `/api/status`, `/api/settings`는 구버전 차단용입니다. `/api/backup` 경로는 변경하지 않습니다.


## v2.2.2 업데이트 전달

페이지 새로고침 때는 최신 버전 존재 여부만 확인합니다. 실제 ZIP은 업데이트 시작 시 Cloudflare Pages가 가져오며, 서버의 `UPDATE_PACKAGE_KV`와 확장의 `chrome.storage.local`에 버전별로 캐시됩니다.
